# Architecture Decision Log

Architecture Decision Records (ADRs) document long-lived technical decisions.

## When to Write an ADR

Create or update an ADR when a change affects:

- architecture boundaries or folder conventions
- security or authorization model
- backend/runtime choice
- testing/deployment policy with architectural impact

## Status Lifecycle

- `Proposed`
- `Accepted`
- `Rejected`
- `Superseded`

Accepted ADRs are not edited for new decisions. Create a new ADR and mark the old one as superseded.
